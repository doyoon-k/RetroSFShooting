# LAST ARK — 스테이지 설계와 밸런스 검증

최종 설계 갱신: 2026-10-05. 조사 근거는 [슈팅게임 디자인 리서치](SHMUP_DESIGN_RESEARCH.md). 이 문서는 현재 구현의 기준이며, 과거 적 기획의 수치보다 우선한다.

## 목표 경험

**조준을 유도하고 → 열린 사격 축을 잡고 → 위험원을 먼저 파괴하고 → 공격이 끝나면 접근한다.**

156초의 스크롤 구간과 미들 3회, 보스 2단계. 13종의 적 외형, 97개 편대의 298기와 직접 배치 2기를 사용한다. 스토리·파일럿·엔딩은 기존 규칙을 따른다. 이번 작업은 밀도와 회복 가능성을 계측하는 플레이테스트용 레벨 개정이며, 인간 재미 검증을 완료했다는 뜻은 아니다.

## 난이도를 판단하는 기준

목표는 기본 조작을 익힌 플레이어가 적의 우선순위와 이동 방향을 계속 선택하는 첫 스테이지다. 보스 강화판은 반복 도전과 패턴 학습을 요구하는 방향의 시안이며, 이전 입문용 회귀 예산을 모두 만족하지는 않는다. 초안은 생존 가능성에 치우쳐 자연 강화 봇의 중반 무타깃 구간이 48.2%, 후반 30.6%였다. 여기서 무타깃은 **살아 있는 적의 중심이 화면 안에 하나도 없는 시간**이며, 잔탄이나 아이템은 포함하지 않는다. 사람이 쉽다고 느낀 관찰과 일치하지만 그 자체가 전체 난이도는 아니다.

- **교전 밀도:** 중반 50~120초와 후반 120~150초에서 자연 강화 회피 봇 기준 무타깃 비율 20% 이하, 평균 화면 적 수 1.5기 이상을 1차 목표로 둔다. 빠른 처치의 보상을 없애려고 모든 순간에 적을 강제 유지하지 않는다.
- **공격 중첩:** 같은 구간에서 서로 다른 적이 최근 2초 안에 발사한 시간 비율 15% 이상을 목표로 둔다. 공격원의 수만 세지 않고 실제 발사를 기록한다. 이 지표도 실제 동시 피격 가능 영역이나 회피 난도를 직접 측정하지는 않는다.
- **저화력 회복:** 직선 LV1·무폭탄 조건과 중반 강제 사망 후에도 완주하는지 검사한다. 적 누적이 지나치면 낮은 화력에서만 회복 불가능해질 수 있다.
- **교전 길이:** 미들·보스는 낮은 화력에서 지루하게 늘어지지 않고 높은 화력에서도 주요 공격을 경험할 시간을 확보한다. 시간 목표는 아래 회귀 예산을 따른다.
- **인간 판정:** 초견에서 피격 이유를 설명할 수 있는지, 먼저 죽일 적을 선택하는지, 강화 후에도 손이 바쁜지, 보급 구간에서 긴장이 풀리는지를 본다. 봇의 무사망에 맞춰 일부러 맞게 만드는 방식으로 난도를 정하지 않는다.

위 수치는 보편적인 슈팅게임 표준이나 연구에서 정해 준 정답이 아니다. 이 프로젝트의 1차 설계 목표이며, 실제 플레이 관찰로 수정한다. 탄속·HP를 일괄 올리는 대신 무발사 소형 편대 28개(146기)와 사격 적 8기를 추가했다. 총 146→300기이며, 추가 소형 편대의 출현 간격은 0.4초다. 서로 다른 높이의 사격원과 겹쳐 사격 축을 선택하도록 배치한다. 첫 유도탄 소개와 보스 직전 보급은 유지한다. 75.5/116/148.5초의 무발사 연결 편대는 기존 보급 사이 공백을 줄인다.

## 주둔형 중형 적 내구도 재조정 (현재)

주둔형 중형 적이 여전히 잘 죽지 않는 플레이 피드백을 반영했다. N3는84→40 HP, N4는92→46 HP로 낮췄다. 직전의 최대 강화 위주 목표는 낮은 강화에서의 긴 교전을 충분히 반영하지 못했다. 현재 목표는 중심 간400px에서 LV3 직선·확산1.5~2.5초, 650px 직선 LV1에서4.5초 이하이며, 공격 묶음 완료를 강제하지 않는다. 통과형 N1/N2/N5는26/30/32 HP다.

`tests/weapon_pressure_probe.gd --mediums`는 중형5종 ×400·650px ×직선·확산 ×LV1·2·3의60조건을 실제 탄 충돌로 측정한다. 플레이어는 무적·정지·지속 사격이며 적의 이동은 정지시킨다. 처치 시간은 회피/조준 손실이 없는 통제 결과다. 원자료는 `build/validation/weapon_pressure_mediums.json`.

| N3 / 400px | 2.93 / 2.10 / 1.60초 | 7.97 / 2.83 / 1.68초 |
| N3 / 650px | 3.67 / 2.67 / 2.02초 | 9.60 / 9.60 / 3.53초 |

60조건 모두90초 안에 격파했다. 주둔형의 근거리 LV3 목표와650px 직선 LV1 목표를 충족했다. 낮은 강화의 먼 확산은 중심탄만 맞아 여전히 느리며, 모든 무기/거리에서 같은 처치 시간을 보장하지 않는다. 이전400px LV1 확산은 N3 16.37초·N4 18.48초였다. `tools/durability.py`의 주둔형 목표도1.5~2.5초로 갱신했다. 기존3~5초/공격 완료 보장은 최신 플레이 피드백에 따라 폐기한다.

## 직전 통과형 내구도 보정 (주둔형 재조정 전)

플레이어 뒤로 지나가는 N1/N2/N5는 짧은 사격 기회에 맞춰 HP를52→26 / 60→30 / 64→32로 낮췄다. 현재 스테이지에서 이 세 종류는 지속적으로 왼쪽으로 이동하는 SINE 동선을 사용한다. 주둔형 N3/N4 및 미들·보스, 자코는 이전 값을 유지한다. 이동 속도와 탄막은 그대로다. 통과형은 집중사격으로 연속 공격을 중간에 끊는 것도 보상으로 허용하며, 이전의 모든 일반 적 첫 연속 공격 완료 기준은 주둔형에만 적용한다.

중심 간400px 정지 표적 LV3 직선/확산 측정: N1 1.13/1.20초, N2 1.27/1.43초, N5 1.28/1.43초. `tools/durability.py`의 통과형 목표는0.9~1.6초, 주둔형은3~5초다.

`tests/flyby_probe.gd`는 실제 기본 이동을 유지하고180px/s 스크롤에 해당하는 적 경로 이동을 추가한다. 플레이어(750,500), 적(1800,500), 첫0.35초 반응 지연 후460px/s로 높이를 따라가며 지속 사격한다. 무적이며 회피는 하지 않는다. 적이 플레이어 앞80px까지 지나가면 실패로 기록하고, 격파는 destroyed 신호로 판별해 화면 밖 제거와 구분한다. 이전 HP/현재 HP 각각3종 ×2무기 ×LV1·3의12조건을 비교하며 무기와 동선은 동일하다.

- 통과 전 격파: 이전4/12 → 현재9/12.
- LV3: 4/6 → 6/6. LV1: 0/6 → 3/6.
- LV1 N1 두 무기와 N5 확산은 여전히 놓쳤다. 조준 지연과 무기 선택의 영향이 남아 있으며 모든 통과 적 격파를 보장하는 설계는 아니다.
- 당시 원자료: `build/validation/before_medium_revision/flyby.json`. 실행: `godot --headless --path . --script tests/flyby_probe.gd --fixed-fps 60`.

## 이전 내구도 개정 (통과형 보정 전 기록)

2026-10-05 비자코의 빠른 격파 피드백 반영. 일반 사격 적 N1/N2/N5는 중심 간400px에서 LV3 직선·확산 지속 사격 시2~3초, 포대 N3/N4는3~5초를 목표로 잡았다. 이동을 멈춘 통제 시험이며 무적이나 최소 생존 시간을 적에게 부여하지 않는다. `python tools/durability.py`는9종 ×2무기 ×2강화의36조건을 실제 충돌로 검사하고, 일반 적 LV3 조건에서는 첫 연속 발사의 마지막 탄까지 나왔는지 확인한다. 원자료는 `build/validation/weapon_pressure_durability.json`.

| 적 | LV3 직선 / 확산 TTK | 완료한 연속 공격(직선 / 확산) |
|---|---:|---:|
| N1 | 2.10 / 2.17초 | 1 / 1 |
| N2 | 2.28 / 2.60초 | 1 / 1 |
| N3 | 3.12 / 3.53초 | 2 / 2 |
| N4 | 3.47 / 4.02초 | 1 / 1 |
| N5 | 2.43 / 2.62초 | 1 / 1 |

미들12~18초·보스25~40초 목표는 **실제 스테이지의 이동하는 적을 직선 LV3로 따라 조준하는 조건**이다. 측정값은 M2 13.03초, M1 14.67초, M3 16.47초, 보스30.63초다. 고정된 보스에게400px 거리에서 확산을 전탄 명중시키면17.02초까지 줄어든다. 목표 시간을 모든 무기·거리에서 보장하는 방식은 아니다.

체력만 올린 첫 시안은 자연 강화·LV1 무폭탄·강제 복구 봇이 모두 전멸했다. 이에 큰 적의 순환 마지막인 재조준 연사(pursuit_fan)와 M3 회전탄(brood_spiral) 단계에 추가 재장전2.4초를 넣었다. 개별 탄막의 탄 수·속도·발사 간격은 그대로이며 다음 순환 전 위치를 회복하고 공격할 여유를 준다. 이 변경은 해당 프리셋을 사용하는 패턴 실험실에도 적용된다. 발사 완료 카운터는 한 연속 공격의 마지막 발사에서 증가하며 보스 단계 변경에도 누적된다. 후속 탄의 명중이나 부화 완료 횟수를 뜻하지 않는다.

이후 자연 강화와 강제 복구 조건은 완주했지만 저화력·회복 손실 목표는 미달이다. **내구도 목표 달성은 전체 밸런스 완료를 뜻하지 않는다.** 아래 생존 결과를 함께 확인한다.

## 직전 강화 공급과 근접 화력 개정 (내구도 변경 전 기록)

내구도 변경에 앞선 2026-10-05 개정에서는 적 체력과 무기의 기본 탄 피해·연사 간격·탄 수를 유지하고 다음 두 변수를 조정했다.

1. **일반 강화 공급 6→5회.** 17초 운반체의 드롭을 제거했다. 공급은7초, 첫 미들(34초) 격파, 둘째 미들(78초) 격파, 셋째 미들(120초) 격파,150초 운반체다. 보급 출현 시각과 실제 획득 시각은 다르다. 사망하지 않는 일반 진행에서 첫 미들 진입 전에 얻을 수 있는 강화는 하나(LV2)이며, LV3는 첫 미들 격파 보급부터 가능하다. 사망 시 회수 아이템은 기존 규칙을 유지한다.
2. **근접 보너스 축소.** 탄 발사점→명중 지점의 거리가80px 이하면1.6배,360px 이상이면1배, 사이에서는 선형 보간한다. 이전 값은160px/2배와640px/1배였다. 큰 적은 충돌 경계가 앞에 있어 함체 중심 간 거리보다 탄 비행거리가 짧다는 점을 고려했다.

최대 강화에서 직선은2→4발, 확산은3→7발이 된다. 전부 맞는 상황의 확산 성장률이 더 크므로, 탄 수와 연사감을 일괄 약화시키기 전에 가까이서 여러 발이 겹쳐 맞을 때의 추가 배율을 먼저 낮췄다. 원거리 LV1까지 함께 약화시키거나 모든 적의 HP를 올리지는 않았다.

### 화력 원인 분리 시험 (이전 HP에서의 기록)

`python tools/weapon_pressure.py`는 N2/N4/보스, 함체 중심 간400/650/900px, 직선/확산, LV1/3의36개 조합을 이전 근접 곡선과 현재 곡선으로 각각 실행한다. 플레이어는 무적·정지·지속 사격, 적의 이동만 정지하며 실제 탄과 충돌 판정을 사용한다. 과거 곡선 비교도 현재 적 HP와 무기 데이터를 사용하므로 **근접 배율의 영향만** 분리한다. 90초 안에 잡지 못하면 처치 시간을 null로 기록하며90초 클리어로 표시하지 않는다.

| 조건 | 이전 처치 시간 | 수정 후 처치 시간 |
|---|---:|---:|
| 보스 / LV3 직선 / 400px | 8.87초 | 12.55초 |
| 보스 / LV3 확산 / 400px | 6.98초 | 10.02초 |
| 보스 / LV3 직선 / 650px | 12.27초 | 16.95초 |
| 보스 / LV3 확산 / 650px | 14.02초 | 18.92초 |
| N2 / LV3 직선 / 400px | 0.62초, 발사 전 격파 | 0.78초, 첫 발사 후 격파 |
| N4 / LV3 직선 / 400px | 0.95초, 발사 전 격파 | 1.28초, 첫 발사 후 격파 |

위 표는 N2 18 / N4 28 / 보스400 HP 당시 기록이다. 현재 HP로 다시 실행하면 시간이 달라진다. 당시900px 조건은 전 조합에서 이전과 동일했다. LV1 확산의 원거리 보스전은 이전과 현재 모두90초 안에 끝나지 않았다. 즉 모든 무기가 모든 거리에서 강하다는 문제는 아니며, 무기 선택과 거리의 영향을 구분해야 한다. 이 시험은 적이 움직이거나 플레이어가 회피하는 실제 교전 시간과 다르다. 실제 스테이지 N4의 진입/주둔 규칙까지 포함한 첫 발사 보장은 아니다.

## 추가한 공격과 이동

### 재조준 연사 — tracking_stream

3회 발사, 회차 간격 0.32초, 각 회차에 현재 위치를 조준. 고정 연사처럼 한 번만 피하고 멈추면 후속탄이 새 위치로 온다. 탄 자체가 비행 중 추적하는 것은 아니다. N2와 M2에서 사용한다.

### 중앙 통로 — gate_fan

왼쪽 기준 -39°, -13°, +13°, +39°로 4발을 쏜다. 움직이지 않는 총구라면 300px 거리에서 중앙 두 탄의 중심 간격은 약 135px다. 플레이어의 변환 후 기본 반지름 21과 적탄 반지름 7을 고려해도 단독 패턴에서는 통과 여유가 있다. 다른 적·몸통·잔탄과의 조합은 별도로 검증한다.

### 회전 부채꼴 — sweep_fan

예고 시작의 조준 방향을 중심으로 3발씩 4회, 0.26초 간격, 회차마다 10° 회전. 전체 중심은 -15°에서 +15°로 움직인다. 마지막 발사 이후 2.8초 회복을 둔다. N4에서 사용한다. 보스 전반은 이후 함대 패턴으로 교체했다.

### 이동 포대 — STRAFE_EXIT

260px/s로 지정 위치에 진입, 카메라 이동을 따라가며 85px 진폭·0.18Hz로 4초간 상하 이동, 이후 오른쪽으로 퇴장한다. 진입·퇴장 중에는 발사를 억제한다. 기본 N4 발사 지연과 회복 주기에서는 주둔 중 한 묶음을 발사한다. 프리셋을 수정하면 발사 횟수도 바뀔 수 있다.

`follow_scroll`은 ENTER_HOLD_EXIT에도 적용 가능하다. N3 상하 프리셋은 화면 위치를 4.5초 유지한 뒤 오른쪽으로 퇴장한다. 기존 LINEAR/SINE/PATH와 미들·보스의 움직임은 기존 좌표 의미를 유지한다. 새 모드는 enum 끝에 추가해 저장된 기존 모드 번호를 보존했다.

부화탄은 300px/s로 0.85초 이동한 다음 0.65초 정지하며 빛과 방사 방향선으로 예고한다. 이후 120° 범위에 7발의 일반탄(340px/s)을 발사하고 사라진다. 자식은 다시 분열하지 않는다. 폭탄/탄 소거, 화면 이탈, 부화 전 충돌은 후속 발사를 취소한다. 순간적으로 플레이어 옆에 예고 없이 새 발사점이 나타나는 방식은 사용하지 않았다.

봉쇄벽의 통로 중심 변화는 가장 느린 시작 파일럿의 460px/s로 다음 벽 도착 전에 이동 가능한지 수치 검사한다. 이것은 단독 벽에 대한 검사이며, 잔탄·조준탄·보스 몸체까지 포함한 전체 회피 가능성의 증명은 아니다.

대형 함대의 V자 진형 전환, 호위함 소환, 모선의 파괴 가능한 기관은 확장 후보로 남겼다. 이번 범위는 기존 적의 움직임을 유지하면서 전투 역할을 공격에 반영하는 것이다.

## 공정성과 가독성

- 기본 예고는 0.35초. 고정 방향은 청록, 예고 시 조준 고정은 노랑, 발사마다 재조준은 분홍이며 총구에 짧은 방향선이 나타난다.
- 적 일반탄은 반지름 7의 충돌 판정을 유지하고, 밝은 중심·분홍 몸체·어두운 외곽을 추가했다. 시각 변경이 통과 가능한 틈을 바꾸지 않는다.
- 화면 안쪽 32px 발사 경계, 일반 적 후방/160px 근접 발사 억제를 유지한다. 미들·보스는 근접 억제 예외다.
- 공격 패턴은 리소스, 각 적의 타이머·목표는 발사기 인스턴스가 소유한다.
- 회전 4방향은 8회에서 6회로 줄이고 0.24초 간격·2.2초 회복으로 정리했다.
- 최초 유도탄은 스크롤 85초이며 다른 N5가 이보다 먼저 등장하지 않도록 회귀 검사를 추가했다.

## 좌표와 속도

현재 전투 영역은 `Rect2(440, 24, 1464, 952)`, WaveSequence·PlacedEnemies 오프셋은 `(416, -32)`다. 편대 첫 출현 시간은 `(마커의 월드 X - 1904 - 80) / 180`이다. 따라서 아래 표의 **마커 로컬 X = 1568 + 180 × 스크롤 초**, 실제 화면 Y = 로컬 Y - 32다. 편대 내부 출현 간격은 spawn_offset.x / 180이다.

스크롤 180px/s. 일반탄 월드 340, 링 250, 유도 260, 플레이어탄 1050px/s. 왼쪽 직선 일반탄은 카메라에 대해 정지한 플레이어에게 이동 구간에서 520px/s로 접근하고 정지 교전에서는 340px/s로 접근한다. 대각탄은 벡터로 계산한다.

## 재현 방법과 판정 범위

```powershell
python tools/check.py
python tools/balance.py
```

`check.py`는 Godot import와 통합 회귀 검사. `balance.py`는 실제 전투 속도(고정 60 physics FPS, 시간 가속 없음)의 6개 조건을 실행하고 `build/validation/balance_suite.json`과 개별 로그를 남긴다. 헤드리스 실행은 벽시계 시간만 더 빠를 수 있다. 렌더링 옵션은 일반 회피 조건의 6개 주요 장면을 `build/screenshots/balance_*.png`로 저장한다.

|---|---|---|
| aim_lv1 / aim_lv3 | 무적, 직선 무기, 강제 LV1/3, 폭탄 미사용 | 동일한 조준 이동에서 화력·교전 길이 비교. 생존 증거 아님 |
