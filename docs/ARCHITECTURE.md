# 구조와 진행 규칙

## 수명과 소유권

`Main`은 계속 유지되며 ScreenHost 안의 화면만 교체합니다. 화면 간 전환은 각 화면의
결과 시그널을 Main이 연결합니다. SaveStore는 Main의 자식입니다. Autoload는 사용하지 않습니다.

| 대상 | 소유자 | 수명 |
|---|---|---|
| 제작용 Resource | 씬/카탈로그의 참조 | 읽기 전용 설정 |
| RunState | Main | NEW GAME부터 Result까지 |
| SortieState | RunState | 파일럿 한 번 출격 |
| 적·플레이어 | Stage의 Actors | 생성부터 제거까지 |
| 탄환 | Stage의 Projectiles | 발사부터 충돌/소멸까지 |
| 아이템 | Stage의 Items | 생성부터 획득/수명 만료까지 |
| 공격 타이머 | 각 EnemyShooter | 해당 적의 수명 |

캐릭터 선택 화면부터 생존 상태는 같은 RunState로 전달됩니다. UI는 표시와 요청을 담당하며,
파일럿 사망과 출격 확정은 Stage가 처리합니다. 생존자 수는 파일럿 목록과 사망 ID 목록에서
계산하므로 별도 카운터를 동기화하지 않습니다.

설정 Resource에 현재 HP, 발사 타이머, 사망 여부 등을 기록하지 않습니다. 파일럿을 교체할
때 Stage를 다시 로드하지 않고 새 Player와 SortieState만 생성합니다. 적·보스 HP와 웨이브
진행은 그대로 유지됩니다. 새 출격 시 기존 적 탄환은 제거합니다.

## 전투 진행

Stage의 Phase는 Launching, Playing, BossIntro, PlayerDying, SelectingNext, Clearing,
Finished입니다. 사용자 Pause는 별도 값이며 Playing 중에만 전환할 수 있습니다.

Stage와 Presentation/UI는 Always, Simulation은 Pausable입니다. 전투가 아닐 때나 사용자
Pause 중에는 SceneTree.paused를 켭니다. 따라서 이동·충돌·발사·웨이브·아이템 수명이 함께
멈추고, 연출과 선택 카운트다운은 진행합니다. Stage 종료 시 Pause를 해제합니다.

Stage는 기본적인 연출 시간을 GameRules에서 읽습니다. 발진 중 기체 위치는 Stage가 제어하고,
발진 완료 후 PlayerShip이 이동을 이어받습니다. 출격 무적은 연출이 끝날 때부터 시작됩니다.

## 피해·사망·동시 사건

Player는 피해를 한곳에서 처리합니다. 무적일 때 피해를 무시하고, Shield가 있으면 Shield만
소모합니다. Shield 소모에도 피격 무적을 부여하여 한 프레임의 중첩 충돌로 HP까지 잃지 않게
합니다. 새 무적은 현재 남은 무적보다 짧아지지 않습니다.

치명타 시 위치와 강화 레벨을 보관하고 죽음 사건을 한 번만 알립니다. Stage는 해당 프레임의
사망/보스 처치 사건을 모아 deferred 처리합니다. 보스와 플레이어가 동시에 죽으면 파일럿
사망 연출과 사망 반영을 먼저 하고, 남은 생존자를 기준으로 엔딩을 결정합니다. 마지막
파일럿까지 죽었으면 보스 처치 여부와 관계없이 전멸 엔딩입니다.

보스 등장 예정 시각과 플레이어 사망이 겹치면 등장 요청을 보관했다가 재출격 후 실행합니다.
Area2D 충돌 콜백에서 적이 죽어 아이템이 떨어질 때에는 물리 쿼리가 끝난 뒤 아이템을 생성합니다.

## 파일럿 교대

사망 위치에서 `이전 레벨 - 1`개의 Power Up을 생성합니다. 콕핏 연출 완료 후 파일럿을 사망
처리하고, 생존자가 있으면 5초 선택을 엽니다. 시간 초과 시 현재 포커스의 생존 파일럿을
선택하며, 유효하지 않으면 명단 순서상 첫 생존자를 선택합니다.

새 SortieState는 HP 2, Power LV1, Bomb 2, Shield 없음으로 시작합니다. 값은 GameRules와
WeaponData에서 조절합니다. 남아 있던 아이템은 새 Player를 유도 대상으로 사용합니다.

## 엔딩과 기록

| ID | 조건 |
|---|---|
| extinction | 생존자 0명 |
| last_signal | 보스 클리어, 생존자 1명 |
| betrayal | 보스 클리어, 생존자 2명, AI 포함 |
| unknown_horizon | 보스 클리어, 생존자 2명(AI 제외) 또는 3명 |
| cost_of_dawn | 보스 클리어, 생존자 4~5명 |
| new_home | 보스 클리어, 생존자 6명 |

Stage 종료 이후에는 Run의 생존 정보를 변경하지 않습니다. 엔딩 이야기 안에서 일어나는
사건은 스테이지 종료 당시의 생존자 결과와 별개입니다.

Ending 연출을 끝내고 Result에 들어갈 때 해금하고 저장합니다. SaveStore는 버전과 엔딩 ID
목록만 ConfigFile로 저장합니다. 임시 파일 저장 후 교체하며, 읽기 실패나 알 수 없는 버전은
기존 파일을 덮어쓰지 않습니다. 중간 Run 저장은 구현 범위에 포함하지 않습니다.

## 검증 범위

자동 검사는 모든 64가지 생존 조합, 파일럿 교대, 타이핑 입력 의미, 메뉴 전환, 무적/Shield,
탄환 충돌, 차지 공격, 공유 패턴 독립성, Pause 수명 정지, 동시 사망 순서, 전체 45기 웨이브,
보스 페이즈, 클리어/전멸 결과 저장을 포함합니다. 렌더링 검사는 같은 흐름의 스크린샷을 남깁니다.
게임패드 실물 입력, Steam Deck 성능과 최종 난이도/아트 품질은 별도의 플레이테스트 대상입니다.
