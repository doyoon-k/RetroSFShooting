# 구조와 진행 규칙

## 수명과 소유권

`Main`은 계속 유지되며 ScreenHost 안의 화면만 교체합니다. 화면 간 전환은 각 화면의
결과 시그널을 Main이 연결합니다. SaveStore는 Main의 자식입니다. Autoload는 사용하지 않습니다.

| 대상 | 소유자 | 수명 |
|---|---|---|
| 제작용 Resource | 씬/카탈로그의 참조 | 읽기 전용 설정 |
| RunState | Main | NEW GAME부터 Result까지 |
| SortieState | RunState | 파일럿 한 번 출격 |
| 적·플레이어 | Stage의 Actors | 생성부터 제거까지 |
| 탄환 | Stage의 Projectiles | 발사부터 충돌/소멸까지 |
| 아이템 | Stage의 Items | 생성부터 획득/수명 만료까지 |
| 공격 타이머 | 각 EnemyShooter | 해당 적의 수명 |

M1의 `SiegeShooter`는 `EnemyShooter`의 벽 발사와 입구 선택을 재사용하며, 유인·교차·분열
삼단 도약탄과 세 벽 조합의 상태와 자신이 만든 탄 참조를 소유합니다. 벽 소멸 뒤 추가 공격을 허용하고,
부화탄이 알린 자식 탄까지 소멸한 뒤2초 반격 시간을 시작합니다. `BroodCore.hatch_held`는
노드별 부화 대기 상태이며 Resource에 저장하지 않습니다. 해제 후에만 부화 예고 시간이
진행하고, 소거된 핵은 자식 탄을 만들지 않습니다. 명시적 공격 프리셋은 일반 시퀀스로
전환하여 Enemy Lab과 웨이브 오버라이드 동작을 유지합니다.

`RicochetCore`는 발사 시 전투 영역과 반사 방향을 확정하고 노드별 반사 횟수·정지 시간을 소유합니다.
미리 계산한 벽까지의 이동을 적분해 넘침 없이 세 번 반사하며, 반사 예고 후 일반탄 한 세대만 생성합니다.
폭탄·피격·화면 이탈·수명 만료로 소거되면 대기 중 잔탄도 취소합니다. `EnemyShooter`는 자신이 만든
탄과 `offspring_spawned` 자식 참조를 추적합니다. 도약탄 충전 전에는 앞선 가족을 기다리고,
`AttackPattern.wait_for_clear`는 해당 가족 전체 소멸 후 `recovery`를 시작합니다. 보스 단계가 바뀌어도
진행 중 도약탄의 대기 장벽과 반격 시간은 유지하고 공유 Resource에는 상태를 쓰지 않습니다.

캐릭터 선택 화면부터 생존 상태는 같은 RunState로 전달됩니다. UI는 표시와 요청을 담당하며,
파일럿 사망과 출격 확정은 Stage가 처리합니다. 생존자 수는 파일럿 목록과 사망 ID 목록에서
계산하므로 별도 카운터를 동기화하지 않습니다.

설정 Resource에 현재 HP, 발사 타이머, 사망 여부 등을 기록하지 않습니다. 파일럿을 교체할
때 Stage를 다시 로드하지 않고 새 Player와 SortieState만 생성합니다. 적·보스 HP와 웨이브
진행은 그대로 유지됩니다. 새 출격 시 기존 적 탄환은 제거합니다.

## 전투 진행

Stage의 Phase는 Launching, Playing, BossIntro, PlayerDying, SelectingNext, Clearing,
Finished입니다. 사용자 Pause는 별도 값이며 Playing 중에만 전환할 수 있습니다.

Stage와 Presentation/UI는 Always, Simulation은 Pausable입니다. 전투가 아닐 때나 사용자
Pause 중에는 SceneTree.paused를 켭니다. 따라서 이동·충돌·발사·아이템 수명과 카메라 전진이
함께 멈추고, 연출과 선택 카운트다운은 진행합니다. Stage 종료 시 Pause를 해제합니다.

Stage의 진행 X좌표가 카메라와 플레이어의 자동 전진을 결정합니다. WaveSequence의 마커와
PlacedEnemies의 직접 배치 적은 화면 오른쪽 경계가 해당 월드 X좌표에 가까워질 때 활성화됩니다.
BossMarker에 도달하면 전진을 멈추고 보스전을 시작합니다.

Stage는 기본적인 연출 시간을 GameRules에서 읽습니다. 발진 중 기체 위치는 Stage가 제어하고,
발진 완료 후 PlayerShip이 이동을 이어받습니다. 출격 무적은 연출이 끝날 때부터 시작됩니다.

## 피해·사망·동시 사건

Player는 피해를 한곳에서 처리합니다. 무적일 때 피해를 무시하고, Shield가 있으면 Shield만
소모합니다. Shield 소모에도 피격 무적을 부여하여 한 프레임의 중첩 충돌로 HP까지 잃지 않게
합니다. 실드 없는 피격은 HP와 두 무기의 공유 강화 레벨을 각각 1씩 줄입니다. 새 무적은 현재 남은 무적보다 짧아지지 않습니다.

치명타 시 위치, 피격 전 강화 레벨과 폭탄 수를 보관하고 죽음 사건을 한 번만 알립니다. Stage는 해당 프레임의
사망/보스 처치 사건을 모아 deferred 처리합니다. 보스와 플레이어가 동시에 죽으면 파일럿
사망 연출과 사망 반영을 먼저 하고, 남은 생존자를 기준으로 엔딩을 결정합니다. 마지막
파일럿까지 죽었으면 보스 처치 여부와 관계없이 전멸 엔딩입니다.

보스 등장 예정 시각과 플레이어 사망이 겹치면 등장 요청을 보관했다가 재출격 후 실행합니다.
Area2D 충돌 콜백에서 적이 죽어 아이템이 떨어질 때에는 물리 쿼리가 끝난 뒤 아이템을 생성합니다.

## 파일럿 교대

사망 위치에서 `max(0, 피격 전 레벨 - 2)`개의 Power Up과 `max(0, 남은 폭탄 수 - 1)`개의 Bomb을 생성합니다. 강화 레벨 - 1을 Power Up 보유량으로 계산하며, 각 보유량에서 1개씩 잃고 남은 수만 떨어뜨립니다. 콕핏 연출 완료 후 파일럿을 사망
처리하고, 생존자가 있으면 5초 선택을 엽니다. 시간 초과 시 현재 포커스의 생존 파일럿을
선택하며, 유효하지 않으면 명단 순서상 첫 생존자를 선택합니다.

새 SortieState는 HP 2, 공유 Power LV1, 직선형 선택, Bomb 2, Shield 없음으로
시작합니다. 값은 GameRules와 각 WeaponData에서 조절합니다. Power Up은 두 무기를 함께
강화하며, 남아 있던 아이템은 새 Player를 유도 대상으로 사용합니다.

폭탄은 최대 4개까지 보유하며, 시작 보유량과 아이템 획득 모두 이 한도를 적용합니다.
전투 콘솔의 네 칸은 보유량에 맞춰 오른쪽부터 채워지며, 폭탄을 쓰면 채워진 칸 중 왼쪽부터 사라집니다. 다음에 사용할 가장 왼쪽 폭탄을 밝게 표시합니다.

폭탄은 입력 시 1개를 소모하고 0.2초 준비 후 피해·탄 소거·1초 무적을 적용합니다. 재사용 대기는 입력 시점부터 1.5초이며, 준비 중과 재사용 대기 중에는 버튼과 밝은 폭탄 표시를 비활성화합니다. 준비 중에도 피격될 수 있으며 사망·클리어 시 예약된 폭발을 취소합니다. 두 타이머는 Playing 중에만 진행하므로 일시정지와 보스 등장 연출 중에는 멈추고, 새 파일럿 출격 시 초기화합니다.

## 엔딩과 기록

| ID | 조건 |
|---|---|
| extinction | 생존자 0명 |
| last_signal | 보스 클리어, 생존자 1명 |
| betrayal | 보스 클리어, 생존자 2명, AI 포함 |
| unknown_horizon | 보스 클리어, 생존자 2명(AI 제외) 또는 3~4명 |
| cost_of_dawn | 보스 클리어, 생존자 5명 |
| new_home | 보스 클리어, 생존자 6명 |

인트로는 `introStory01~09.png`, AI 포함 2명 생존은 `WithAi01~04.png`,
그 외 2~4명 생존은 `234ed01~04.png`, 5~6명 생존은 `56ed01~04.png`를
번호순으로 표시합니다. 5명과 6명 엔딩은 그림을 공유하고 자막과 저장 ID는 각각 유지합니다.
전멸과 1명 생존은 대응하는 원본 그림이 없어 Illustration을 비워 두었습니다.
임시 SVG는 제거했으며, 스토리 본문과 파일럿 대사는 번호 문구로 표시합니다.
StoryScreen은 그림의 비율을 유지하여 화면 전체에 표시하고, 하단에 자막을 겹칩니다.
Space, 게임패드 A, 다음 버튼은 타이핑 중에는 본문을 완성하고, 완료 후에는 다음 컷으로 넘깁니다.

Stage 종료 이후에는 Run의 생존 정보를 변경하지 않습니다. 엔딩 이야기 안에서 일어나는
사건은 스테이지 종료 당시의 생존자 결과와 별개입니다.

Ending 연출을 끝내고 Result에 들어갈 때 해금하고 저장합니다. SaveStore는 버전과 엔딩 ID
목록만 ConfigFile로 저장합니다. 임시 파일 저장 후 교체하며, 읽기 실패나 알 수 없는 버전은
기존 파일을 덮어쓰지 않습니다. 중간 Run 저장은 구현 범위에 포함하지 않습니다.

## 검증 범위

자동 검사는 모든 64가지 생존 조합, 파일럿 교대, 타이핑 입력 의미, 메뉴 전환, 무적/Shield,
탄환 충돌, 무기 변경·공유 강화, 공유 패턴 독립성, Pause 수명 정지, 동시 사망 순서, 전체 300기 공간 배치,
보스 페이즈, 클리어/전멸 결과 저장을 포함합니다. 렌더링 검사는 같은 흐름의 스크린샷을 남깁니다.
게임패드 실물 입력, Steam Deck 성능과 최종 난이도/아트 품질은 별도의 플레이테스트 대상입니다.
